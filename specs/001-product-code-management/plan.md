# Implementation Plan: Product Code Management

**Branch**: `main` (actual Git branch) | **Date**: 2026-10-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-product-code-management/spec.md`.
The setup script reports feature context `001-product-code-management`; it did not switch Git branches.

## Summary

Extend the existing Product flow with `code: string | null` in reads and a required string on
create. Keep legacy values null at rollout; require assignment on their next edit. Enforce
case-insensitive uniqueness in PostgreSQL across active and deleted products. Add on-demand
internal EAN-13 generation with prefix `20`, a bounded sequence, and a pure checksum helper.
Use the existing API/service/repository, Ant Design, and React Query boundaries without new dependencies.

Phase 0 research and Phase 1 design are complete in the linked artifacts. No source, migrations,
database records, or dependency files have been changed by this planning run.

## Technical Context

**Language/Version**: Strict TypeScript 5; React 19.1.0; Next.js 15.5.26 App Router.

**Primary Dependencies**: Existing Ant Design 5, TanStack React Query 5, NextAuth 5 beta,
Drizzle ORM 0.45.3 / Kit 0.31.11, Neon serverless driver. No new packages.

**Storage**: Existing Neon PostgreSQL through `src/server/db/index.ts` HTTP connection.
Nullable Product code, expression unique index, and separate bounded PostgreSQL sequence.
No interactive transaction or WebSocket pool is needed for single-row Product saves or nextval.

**Testing**: Existing `node:test`/TypeScript-transpilation approach; planned Product service suite,
real test-database verification for index/concurrency, and manual browser/route checks.

**Target Platform**: Existing Next.js server runtime and browser dashboard; no deployment change.

**Project Type**: Single Next.js web application with route/service/repository backend.

**Performance Goals**: Index-based code lookup; generation makes at most 32 candidate attempts
per request. One Generate click fills an empty input; no new catalog-wide queries per list row.
No unsupported latency or production throughput guarantee is assumed.

**Constraints**: 1–100 ASCII alphanumerics after outer trim; preserve case/zeros; uniqueness is
case-insensitive across all products. Generated format is 20 + ten digits + checksum. Preserve
permissions, envelopes, stock behavior, snapshots, pagination, and name-only search.

**Scale/Scope**: One Product feature, one nullable column, one unique index, one format check,
one sequence, one new generation endpoint. Ten billion sequence positions (0–9,999,999,999);
no catalog size assumption is necessary for correctness. Generation consumes positions even if
canceled; it never reserves or writes a Product.

## Complexity Tracking

No Constitution Check violations; no additional architecture exceptions required.

Implementation sequencing: reviewed additive schema migration first; model/repository/service
and HTTP contracts next; form/list integration after; then verification/documentation. Type both
create and update client payloads in T009 before typed form work in T011; T016 retains edit behavior
and cache verification. Guarded legacy updates that affect zero rows must distinguish still-uncoded
400, missing/deleted 404, and concurrently assigned 409. The latter displays "Product Code was assigned by another request. Refresh and retry manually."
and requires user refresh/manual retry without automatic save retries or further writes. Regression
and live-race validation must cover all three outcomes. Rollout
must deploy the schema before code that selects `code`, and coordinate retiring old writers,
which can still create null-coded products until the application deployment is complete.
